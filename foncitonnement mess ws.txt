probleme:

coté sender = acces seulement à une liste de clients ws
impossible de faire lien avec client/user specifique EN DEHORS de ressource id, qui est succeptible de se repeter

comment eviter que le message s'envoie a quelqu'un d'autre ou ne s'envoie pas en cas extreme ou deux user ont le meme id (e.g. serveur restart)


-> sender se connecte ->ressourceId attribué
-> receiver se connecte ->ressourceId attribué
-> conversation commence, envoie basé sur ressourceId (check si une des ressources connecter correspond dans liste du user)


-> receiver se deconnecte et se reconnecte alors que sender et rester connecter et se refere donc toujours a resourceId de base : 
si un des ressourceId correspond a ceux lister dans receiver, on envoie a celui la, sinon on enregistre juste le message et notifie plus tard . En thoerie 
aucune chance que quelqu'un recupere ressource id similaire tant que serveur pas déconnecter

->si ws se deco et que tout les ressourceID sont reinitialiser : sender deconnecter, doit relancer la session
-> Cependant si l'un n'est pas connecter au moment d'envoyer, possibilité qu'un meme ressourceid soit present dans deux client a la fois
-> (assuming that ressource id is an object) Si timestamps plus recent pour un qui n'est pas client => ne pas envoyer


en résumé :

Connection : enregitrement d'un nouveau RessourceId() (id + timestamp)
Envoie message recupérer convo, check dans user qui n'est pas le sender si client avec ressourceId correspondant
Si correspond -> checker qu'il n'y en ai pas un autre avec timestamp plus recent, dans quel cas on envoie pas
Si envoie et sur la page de convo => mise a jour de la vue de la convo
Si envoie et pas sur page de convo => notif
Sinon enregistrer le message dans convo, notifier si convo a message not read (en front ou a prochaine co)
